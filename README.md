# KinoTime — полный серверный комплект, 17 октября 2026

Это сервер бота и веб-панель, включая последние изменения из двух чатов разработки.
Лаунчера Windows, мастерских нарезок и мемов, видео и рабочей базы здесь нет.

## Установка на Bothost

1. Остановите бот. Сохраните имеющуюся базу, её WAL/SHM и настройки отдельно.
2. Загрузите содержимое этого архива в корень проекта: рядом должны лежать app.py,
   Dockerfile, папки data, database, handlers, services и webpanel. Это полный комплект.
3. Задайте BOT_TOKEN существующего бота и ADMIN_IDS=6887112241 в переменных хостинга.
   Либо впишите свой токен в data/config.py. В архиве токен намеренно пустой.
4. Включите WEB_ENABLED=1, WEB_HOST=0.0.0.0, WEB_PORT=3000 и укажите свой
   HTTPS-адрес в WEB_PUBLIC_URL. Порт маршрута домена должен совпадать с WEB_PORT.
5. DATABASE_PATH должен указывать на ВАШУ рабочую базу в постоянном хранилище.
   Если хостинг сохраняет /app/data, используйте /app/data/bot.sqlite,
   BACKUP_DIR=/app/data/backups и UPLOAD_DIR=/app/data/uploads.
   Уточните фактическую постоянную папку в настройках хостинга.
6. Папка data содержит также программные файлы __init__.py, config.py, settings.py.
   Они обязательны. Если подключённый том скрывает /app/data, скопируйте эти три
   файла в него с сохранением своей базы и настроек. Нельзя заменять весь том пустой папкой.
7. Пересоберите образ и запустите бот. Без Docker: Python 3.11,
   python -m pip install -r requirements.txt, затем python app.py.
8. Откройте /web и обновите страницу Ctrl+F5. Код сам обновляет схему базы.

Файл .env.example — образец; бот сам его не загружает. Без существующей базы
бот создаст пустую: восстановленную базу нужно разместить по DATABASE_PATH ДО запуска.
Работа с Telegram и настройки конкретного хостинга локально не проверялись.

## Восстановленная база и Storage

Готовая база с 13 прежними карточками, 10 пользователями и 1333 ссылками Storage
остаётся в отдельном архиве KinoTime-Recovered-September-And-Storage-2026-10-15.zip,
внутри ready-database/bot.sqlite. Используйте её только если на сервере нет более
новых данных. Перед заменой остановите бот; не подкладывайте старые WAL/SHM к новой базе.

В этот сервер включены services/storage_recovery.py, обновлённый storage_backup.py
и tools/restore_storage.py. Видео выдаются копированием сообщений Storage без скачивания
на компьютер. Бот должен иметь доступ к каналу и исходным сообщениям.

Для импорта инвентаря в существующую базу остановите бот и выполните в том же окружении:
python tools/restore_storage.py --inventory recovery/storage-inventory.json --admin 6887112241 --apply
Инвентарь находится в отдельном архиве KinoTime-Storage-Recovery-1333-2026-10-15.zip.
Команда делает резервную копию существующей базы. Повторный импорт не создаёт дубликаты.
Если готовая база уже установлена, импортировать инвентарь повторно не требуется.
Восстановленные черновики требуют проверки названий, возраста и публикации.

## VPS / Docker Compose

Дополнительный локальный Telegram Bot API входит в compose.yaml. Для него нужны
TELEGRAM_API_ID и TELEGRAM_API_HASH. setup.sh предназначен для собственного VPS,
а не панели Bothost. Перед его запуском укажите токен в data/config.py либо
экспортируйте BOT_TOKEN и ADMIN_IDS в окружение. После настройки они могут храниться
в .deploy.env. Для обычного запуска на Bothost локальный Bot API не обязателен.
