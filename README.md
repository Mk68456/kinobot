# KinoTime / kinobot

Telegram-бот на Python 3.11 и aiogram 2.25.2: каталог фильмов и сериалов, поиск,
карточки TMDB, проверка подписки, роли, админ-панель и рассылки.

Лаунчер 1.3.3: [выбор папок компьютера и запуск подготовки с телефона](docs/REMOTE_RENDER_1_3_3.md).

## Запуск

Локальная мастерская нарезок: [KinoTime Clips](docs/LOCAL_CLIPS.md).
Запуск отдельным окном: `tools/Start-KinoTime-Clips.cmd`.

Отдельная мастерская мемов: [MemeFlow](docs/MEMEFLOW.md).
Пакетное оформление коротких видео с игровым фоном и баннером: `tools/Start-MemeFlow.cmd`.

Токен и список администраторов задаются в `data/config.py`. Права администратора
проверяются по Telegram ID отправителя на каждом административном действии.
Бот работает в личных чатах.

```powershell
uv sync --frozen
uv run --frozen python app.py
```

Если uv не используется: установите Python 3.11, создайте виртуальное окружение,
выполните `python -m pip install -r requirements.txt` и `python app.py`.
`requirements.txt` генерируется из `uv.lock`, не редактируйте его отдельно:

```powershell
uv export --frozen --no-dev --no-hashes --no-emit-project -o requirements.txt
```

Не запускайте несколько экземпляров polling-бота с одним токеном и одной БД.

## Веб-панель загрузки

Для развёртывания на Linux и Windows добавлен [Docker Compose и установщик](docs/DOCKER_SETUP.md):
`bash setup.sh` или `.\setup.ps1`. Повторный запуск с `--update` обновляет сервисы
с сохранением настроек и резервированием рабочей базы.

Панель по умолчанию выключена. [Инструкция запуска](docs/WEB_SETUP.md) описывает
`WEB_ENABLED=1`, локальный Telegram Bot API для загрузок до 2000 МБ и доступ через
HTTPS или SSH-туннель. Файл `.env` автоматически не загружается.

[Инструкция администратора](docs/WEB_ADMIN.md): вход через `/web`, загрузка сезонов,
черновики, публикация и добавление файлов, отправленных через Telegram Desktop
в режиме `/webfiles`. Проверка реальной передачи файлов на 2 и 4 ГБ ещё требуется.

## Роли через админ-панель

Приветствие `/start` настраивается через `/admin` → **🎨 Изменить дизайн**:
фото, текст и предпросмотр. [Инструкция по оформлению](docs/WELCOME_DESIGN.md).

1. Отправьте `/admin` → **Роли пользователей** → **Создать роль**.
2. Введите название. У новой роли проверка подписки включена.
3. Откройте роль и нажмите **Освободить от подписки**, если это необходимо.
4. В списке ролей нажмите **Роль пользователя**, введите Telegram ID и выберите роль.
   ID можно скопировать из **Статистика → Список пользователей**.
5. В том же экране можно **Снять роль**. В карточке роли доступны переименование,
   включение проверки подписки и удаление с подтверждением.

У пользователя одна роль. Он должен хотя бы один раз отправить боту `/start`.
Без роли подписка обязательна. Настройка роли применяется немедленно ко всем её
пользователям, включая скачивание по ранее полученным кнопкам. Удаление роли снимает
назначения и возвращает обязательную проверку подписки. Если обязательных каналов
нет, доступ открыт всем. Роли не дают права администратора; список администраторов
по-прежнему задаётся в конфигурации.

## Личные отметки просмотра

В каталоге рядом с фильмами и сериалами отображается ❌ или ✅. На карточке фильма
есть кнопка отметки просмотра. В списке серий кнопка с названием скачивает файл,
а соседняя **Просмотрена** меняет личный статус: `Серия 1 ❌` → `Серия 1 ✅`.
Отметку можно снять. Названия в общем каталоге и статусы других пользователей не меняются.

У сезона показывается прогресс, например `Сезон 1 ❌ (3/10)`. Кнопка **Сезон просмотрен**
отмечает все существующие серии сезона; снятие отметки сезона снимает отметки его серий.
Когда все серии отмечены, сезон получает ✅ автоматически. Весь сериал получает ✅
в каталоге, когда просмотрены все добавленные серии. Новые серии автоматически
просмотренными не становятся. Пустой сезон отметить нельзя. У фильмов озвучки и
качества не считаются отдельными сериями — просмотр отмечается на уровне фильма.

Отметки хранятся в SQLite и сохраняются после перезапуска. Открытие карточки или
скачивание файла само по себе не означает просмотр. Повторное нажатие одной и той же
кнопки не создаёт повторной записи. Проверка доступа и исключения по ролям действуют
так же, как при получении файла.

В админке:

- **Статистика → Отметки просмотра сериалов** — число личных отметок серий по каждому
  сериалу, число пользователей и количество серий в каталоге. Одна серия, отмеченная
  двумя пользователями, даёт две отметки.
- **Статистика → История пользователя → Telegram ID → Какие серии и фильмы просмотрены** —
  количество просмотренных серий по сериалам. Выберите сериал, чтобы увидеть конкретные
  сезоны, серии и даты отметок; отдельно доступны просмотренные фильмы.

Статистика отметок отражает текущее состояние: снятые отметки в неё не входят.
Старая статистика открытий карточек остаётся отдельно. Удаление серии или фильма
удаляет соответствующие отметки.

## База данных и миграции

При обычном локальном запуске используется `bot.sqlite` в корне проекта,
независимо от текущего каталога запуска. Подключение открывается при старте
и закрывается при остановке. SQLite использует WAL и ожидание блокировки до 10 секунд.

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `DATABASE_PATH` | Полный путь к БД; имеет приоритет над `DATA_DIR` |
| `DATA_DIR` | Если задан, БД по умолчанию находится в `<DATA_DIR>/bot.sqlite` |
| `BACKUP_DIR` | Каталог копий перед миграциями; по умолчанию `<DATA_DIR>/backups` |
| `TMDB_API_KEY` | Ключ для автоматического поиска карточек |
| `TMDB_USE_DOH` | `1` — DNS-over-HTTPS, `0` — системный DNS; по умолчанию `1` |

Без `DATA_DIR` служебные данные и резервные копии находятся в `runtime/`.
`.env.example` содержит примеры; файл `.env` автоматически не загружается.

При запуске выполняются нумерованные миграции (`PRAGMA user_version`). Они создают
новую БД с нуля либо обновляют старую. Перед изменением существующей схемы создаётся
согласованная SQLite-копия. Ошибка резервирования или миграции прерывает запуск.
Назначения ролей и задания рассылок хранятся в той же БД.

Резервное копирование вручную, в том числе при работающем боте:

```powershell
uv run --frozen python tools/backup_database.py bot.sqlite --output-dir runtime/backups
```

Для восстановления остановите бота, сохраните текущую БД и её файлы `-wal`/`-shm`
в отдельный каталог, затем поместите резервную копию по `DATABASE_PATH` под именем
рабочей БД. Не оставляйте рядом WAL/SHM от заменённой базы. После запуска миграции
при необходимости выполнятся снова. Регулярно сохраняйте копии вне сервера бота;
автоматические копии перед миграциями не заменяют регулярное резервирование.

## Рассылки

`/admin` → **Рассылка** → отправьте пост → проверьте предпросмотр → подтвердите.
Пост копируется активным пользователям. Источник — исходное сообщение администратора;
не удаляйте его до завершения задания. Служебные сообщения Telegram могут не поддерживать копирование.

**Задания рассылки** показывает последние десять заданий, их прогресс и ошибки.
Можно остановить задание либо повторить неотправленные сообщения завершённого или
приостановленного задания. При перезапуске незавершённые задания продолжаются автоматически.
Подтверждённые успешные отправки не повторяются. При аварии или сетевом тайм-ауте
между фактической доставкой Telegram и сохранением результата возможна повторная доставка.
Остановка не отменяет уже отправленное сообщение и запрос, который уже выполняется.

Ограничение частоты Telegram учитывается через RetryAfter. Сетевые ошибки повторяются
ограниченное число раз и не удаляют пользователей. Если пользователь заблокировал
бота или его аккаунт недоступен, он помечается неактивным; история и роль сохраняются.
Следующий `/start` возвращает пользователя в активные.

## Docker

```sh
docker build -t kinobot .
docker volume create kinobot-data
docker run -d --name kinobot --restart unless-stopped \
  -v kinobot-data:/app/runtime \
  -e TMDB_API_KEY kinobot
```

Образ запускается от пользователя с UID 10001. БД и копии находятся в томе
`/app/runtime`, отдельно от Python-пакета `data`. При использовании bind mount
каталог должен быть доступен на запись UID 10001. Локальные базы, окружение и
кэши исключены из образа через `.dockerignore`. Поэтому первый запуск с пустым
томом создаёт пустой каталог фильмов.

Для переноса существующего локального каталога сначала сделайте SQLite-копию
командой выше и импортируйте её в том до запуска приложения:

```sh
docker create --name kinobot-seed -v kinobot-data:/app/runtime kinobot
docker cp runtime/backups/backup-YYYYMMDDTHHMMSSffffffZ.sqlite kinobot-seed:/app/runtime/bot.sqlite
docker run --rm --user root -v kinobot-data:/app/runtime --entrypoint chown kinobot -R 10001:10001 /app/runtime
docker rm kinobot-seed
```

Используйте реальное имя созданной копии. Не импортируйте поверх работающей БД.
Сборка устанавливает зависимости строго из lock-файла; автоматического перехода
к другим версиям при ошибке нет.

## Структура

```text
app.py                  запуск, миграции, завершение работы
loader.py               явное создание бота и диспетчера
data/                   конфигурация и пути
database/               SQL по сущностям, роли, задания, соединение и миграции
handlers/admin/         роли, рассылки, фильмы, категории, сезоны, торренты
handlers/users/         каталог, поиск, выдача файлов
keyboards/              построение кнопок из переданных данных, без SQL
services/               доступ, подписка, сохранение карточки, рассылки, TMDB
states/                 состояния диалогов
tests/                  проверки БД, сервисов и маршрутизации aiogram без сети
tools/                  резервное копирование
```

SQL-операции остаются синхронными; транзакции не должны содержать `await`.
Страницы каталога выбираются через SQL LIMIT/OFFSET. Нечёткий поиск по названиям
пока выполняется в Python; при большом каталоге его стоит измерить и вынести в
отдельный поисковый индекс. Незавершённые диалоги редактирования хранятся в памяти
и сбрасываются после перезапуска; сохранённые роли и задания рассылки сохраняются.

## Проверки

```powershell
uv run --frozen ruff check .
uv run --frozen python -m unittest discover -s tests -v
```

Тесты не подключаются к Telegram или TMDB, используют фиктивный токен и временные
базы. Проверяются миграции, резервирование, роли, права доступа, выдача файлов,
транзакционное удаление, пагинация и ошибки рассылок. Эти же проверки настроены
для GitHub Actions.
