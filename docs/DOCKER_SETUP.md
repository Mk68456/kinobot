# Развёртывание на Linux и Windows

Один комплект запускает бота, веб-панель и локальный Telegram Bot API в фоне.
Для доступа по домену он также запускает Caddy с автоматическим HTTPS.
Настройки сохраняются в `.deploy.env`, база — в постоянном Docker-томе
`kinobot-data`. Токен и администраторы остаются в `data/config.py`.

## Что установить один раз

- Linux: [Docker Engine](https://docs.docker.com/engine/install/) и
  [Compose plugin](https://docs.docker.com/compose/install/linux/).
  Пользователь установки должен иметь доступ к Docker daemon.
- Windows 10/11: [Docker Desktop](https://docs.docker.com/desktop/setup/install/windows-install/)
  с WSL 2 и Linux containers. Запустите Docker Desktop до установки бота.
- На обеих ОС: Python 3.9+ для установщика либо `uv`. Сам бот работает на
  Python 3.11 внутри контейнера; зависимости бота вручную устанавливать не нужно.
  При использовании `uv` оболочка использует Python из окружения проекта.

Для сборки API нужны интернет, свободное место и достаточно памяти для компиляции
C++. Первая сборка может занять продолжительное время; следующие используют кэш.
API собирается из закреплённой версии официального исходного кода Telegram.

## Первый запуск

Скопируйте проект на хост, проверьте `data/config.py`. Не запускайте одновременно
старого бота и новый контейнер с одним токеном. Если старый бот обслуживается
systemd, отключите его автоматический запуск перед переносом.

Из корня проекта на Linux:

```bash
bash setup.sh
```

На Windows в PowerShell:

```powershell
.\setup.ps1
```

Если Windows блокирует локальный скрипт политикой исполнения, запустите его
однократно командой `powershell -ExecutionPolicy Bypass -File .\setup.ps1`.

Установщик:

1. Проверяет Docker, Linux containers и Compose.
2. Запрашивает `api_id`, `api_hash` с [my.telegram.org](https://my.telegram.org)
   и необязательный домен. `api_hash` вводится скрыто. Настройки сохраняются;
   это отдельные реквизиты от токена бота. Для TMDB при необходимости заполните
   `TMDB_API_KEY` в `.deploy.env` и повторите запуск.
3. Собирает контейнеры. Попросит ввести `STOPPED`, когда старый бот остановлен.
4. Запрашивает путь к существующей SQLite-базе (по умолчанию `bot.sqlite`).
   Укажите реальную базу старого бота; если используется другой путь — введите его.
   `NEW` означает новую базу или использование уже существующей базы Docker-тома.
5. Создаёт согласованную копию исходной базы в `runtime/setup-seed.sqlite`, затем
   импортирует её **только в пустой том**. Существующая база тома имеет приоритет:
   она сохраняется, а перед запуском создаётся копия в `runtime/backups` внутри тома.
6. Запускает локальный API. Для перехода с облачного API запрашивает `LOGOUT`.
   Команда действительно переключает бота; после неё Telegram не разрешает
   возвращаться в облачный API 10 минут. `LOCAL` выбирайте только если этот бот
   уже переведён именно на этот локальный API-сервер.
7. Запускает бота и проверяет HTTP-доступность панели. Отправьте боту `/web`.

Установщик не определяет и не останавливает автоматически старые службы systemd
или чужие контейнеры. При ошибке он прекращает дальнейшие шаги и сохраняет данные;
исправьте причину и запустите его снова. Отметка о переходе на локальный API
сохраняется в `runtime/docker-local-api.ready`, чтобы не повторять `logOut`.
Она относится к текущему боту и текущему API-тому: не переносите её отдельно
на новый сервер и не используйте при смене токена.

Если скрытый ввод `api_hash` не принимает вставку, установщик покажет только
число полученных символов и предложит повторный ввод. Введите `V`, чтобы вставить
ключ в обычное видимое поле (ключ будет виден на экране терминала), или нажмите
Enter для повторного скрытого ввода. `Q` отменяет настройку. Пробелы по краям
и парные кавычки убираются автоматически; внутри ключа допустимы только 32
шестнадцатеричных символа. Не отправляйте ключ или снимок видимого поля в чат.

## С доменом или без него

**С доменом:** введите, например, `kino.example.com`, без `https://` и пути.
DNS должен вести на этот хост. Порты 80/443 должны быть свободны и доступны извне;
при домашнем размещении понадобится настройка маршрутизатора. Caddy получает
и продлевает сертификат. Если на сервере уже есть HTTPS-прокси, не занимайте
его порты вторым прокси: настройте существующий по [ручной инструкции](WEB_SETUP.md)
и установите `WEB_PUBLIC_URL` в `.deploy.env`, оставив `COMPOSE_PROFILES` пустым.

**Без домена:** панель доступна только на компьютере хостинга по
`http://127.0.0.1:8088`. Для Linux VPS откройте на компьютере администратора туннель:

```bash
ssh -N -L 8088:127.0.0.1:8088 USER@SERVER
```

Оставьте туннель открытым и перейдите по ссылке `/web` на этом компьютере.
Порт Bot API 8081 вообще не публикуется на хост. Веб-порт 8088 привязан к loopback.

## Обновление и управление

После замены исходников новой версией выполните:

```bash
bash setup.sh --update
```

Или на Windows:

```powershell
.\setup.ps1 --update
```

Обновление использует сохранённые настройки, собирает образы, останавливает
контейнер бота, резервирует базу и запускает сервисы. `logOut` не повторяется.
После изменения `data/config.py` тоже требуется пересборка: конфиг входит в образ.

Одинаковые команды для обеих ОС:

```text
docker compose --env-file .deploy.env ps
docker compose --env-file .deploy.env logs --tail=100 bot
docker compose --env-file .deploy.env logs --tail=100 bot-api
docker compose --env-file .deploy.env logs --tail=100 caddy
docker compose --env-file .deploy.env stop
docker compose --env-file .deploy.env up -d --wait
```

Параметр `--env-file .deploy.env` обязателен для этого комплекта. Не публикуйте
файл настроек или вывод `docker compose config` с раскрытыми значениями.
Не используйте `down -v` для обычного обновления: эта команда удаляет тома.
Локальная `bot.sqlite` после импорта не является рабочей базой контейнера.

Контейнеры используют `restart: unless-stopped`: они перезапускаются при падении
процесса и старте Docker, кроме явно остановленных вручную. Healthcheck сообщает
состояние, но сам по себе не перезапускает зависший процесс.
[Поведение политик перезапуска Docker](https://docs.docker.com/engine/containers/start-containers-automatically/).

На Linux включите автозапуск Docker средствами вашей ОС (обычно
`sudo systemctl enable --now docker`). На Windows включите запуск Docker Desktop
при входе в систему. **Без входа пользователя обычный Docker Desktop не гарантирует
запуск после перезагрузки Windows.** Для непрерывного хостинга предпочтителен Linux.
Компьютер должен оставаться включённым, без сна, с интернетом.

## Резервные копии и проверка

Сделать резервную копию рабочей базы и выгрузить копии на хост:

```text
docker compose --env-file .deploy.env exec bot python tools/backup_database.py /app/runtime/bot.sqlite
docker compose --env-file .deploy.env cp bot:/app/runtime/backups ./docker-backups
```

Сохраняйте резервные копии вне хоста. Также сохраняйте `.deploy.env`, исходный
конфиг и данные API-тома при планировании переноса на другой сервер.

После установки проверьте `/start`, `/web`, загрузку небольшого файла, публикацию
и выдачу в боте. Затем проверьте большие файлы. Успешный HTTP healthcheck
не подтверждает реальную загрузку 2 ГБ или выдачу 4 ГБ. Эти проверки, сборка
контейнеров и HTTPS требуют рабочего Docker-хоста и реквизитов Telegram;
в среде разработки без Docker они не выполнялись.

Дальнейшая работа администратора описана в [WEB_ADMIN.md](WEB_ADMIN.md).
