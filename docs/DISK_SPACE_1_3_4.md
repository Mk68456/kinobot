# KinoTime Launcher 1.3.4 · 09.10.2026

## Скорость и качество

Раньше строка «около 1400 Кбит/с» обозначала целевой битрейт видео, а не скорость обработки. Для меньшего разрешения используется меньший битрейт: это уменьшает размер файла. В новой версии подпись прямо говорит «целевой битрейт».

Реальная скорость теперь показывается в строке кодирования: например, `2.00× · 60 кадр/с · осталось ~0:15`. Значение 2× означает обработку двух секунд видео за секунду. Остаток времени приблизительный, относится к текущему проходу/файлу, а не ко всему сезону. Показатель появляется, когда FFmpeg выдаёт корректную статистику; при копировании кадров/с может не быть. В точном двухпроходном режиме отдельные этапы сохраняют проценты.

Исходное H.264/yuv420p лаунчер может копировать без перекодирования; создание 720p/480p/360p требует декодирования, уменьшения разрешения и повторного кодирования. Поэтому исходное качество иногда готовится гораздо быстрее меньшего. На скриншоте аппаратный кодировщик не найден, используется процессор. Более низкий битрейт сам по себе не означает более низкую скорость рендера. Диагностика оборудования остаётся доступной через «Проверить» и «Подробнее».

## Очистка и свободное место

В «Настройках» появились:

- «Автоочистка: промежуточные файлы и MP4, подтверждённые ботом» — включена по умолчанию, её можно отключить.
- «Резерв свободного места, ГиБ» — по умолчанию 2; допустимо от 0.25 до 100. После изменения поля нажмите «Сохранить настройки».

После завершения всех озвучек одного качества удаляется промежуточный видеоряд `.video-качество.mp4`. Готовые MP4 с озвучками остаются. При повторной подготовке уже готовых вариантов отсутствие промежуточного файла не вызывает повторное кодирование.

При нехватке места лаунчер удаляет учтённые готовые копии, которые сервер уже подтвердил как принятые ботом. Учитываются также созданные лаунчером копии одного варианта в папках отдельной серии и общего сезона. Удаление локальной принятой копии не удаляет файл в Telegram и не публикует карточку автоматически.

Очистка ограничена файлами, записанными в индекс лаунчера внутри `KinoTime-Ready` и `KinoTime-Prepared`. Исходники, неотправленные и неподтверждённые MP4, изменённые файлы, активный проект и чужие файлы не удаляются. Символические ссылки и junction-переходы не используются для очистки. Занятые Telegram или антивирусом файлы пропускаются.

Перед кодированием и копированием проверяется место под текущий файл и резерв. Во время кодирования свободное место также контролируется. Если его недостаточно, запись останавливается: незавершённый файл будет создан заново после освобождения места, уже завершённые варианты сохраняются. При ожидании лаунчер проверяет диск каждые пять секунд и продолжает автоматически. Кнопка «Стоп» прерывает ожидание.

Если диск заполнен исходниками или ещё не принятыми видео, безопасной очистки может не хватить. Лаунчер будет ждать: потребуется освободить место или отправить предыдущие проекты. Он не начнёт отправку через Telegram автоматически из режима «Подготовить без отправки». Для повторной отправки принятой копии, уже удалённой очисткой, нужно заново подготовить её из исходника.

Старые кеши от предыдущих версий не удаляются массово только по названию папки. Уже готовые варианты индексируются при повторной подготовке, а право на очистку готовых MP4 появляется после проверки серверного подтверждения во время отправки. Локального состояния «отправлено» без ответа сервера недостаточно. База индекса `cache-index.sqlite` хранится в профиле лаунчера и не содержит токенов подключения.

## Установка

1. Дождитесь завершения текущего файла или остановите подготовку. Закройте старый лаунчер.
2. Используйте новый `KinoTime.exe` из архива либо установите `KinoTime-Setup-1.3.4.exe`. Для EXE отдельная установка Python или FFmpeg не нужна.
3. Проверьте версию 1.3.4 в заголовке окна, настройки оборудования и диска. Старые настройки профиля EXE сохраняются; код подключения вводится заново при необходимости.
4. Возобновите проект. Исходники и готовые файлы не нужно удалять вручную перед обновлением.

Для запуска из Python замените содержимое папки `tools` файлами из `Source/tools` архива, включая новый `disk_space.py`. Не копируйте папку Source целиком поверх серверного проекта. Серверную веб-панель и базу бота для этого обновления заменять не требуется. Предыдущие архивы сохранены.
