# KinoTime + Zona + локальный Bot API на Bothost

Этот комплект предназначен для управляемого хостинга Bothost.
Команды `docker info`, `docker compose` и `setup.sh` в веб-терминале не нужны.
Хостинг собирает один образ по корневому `Dockerfile`, внутри работают два процесса:
KinoTime и официальный Telegram Bot API с `--local` на `127.0.0.1:8081`.

## Что входит и что проверено

Архив содержит полный комплект серверных исходников текущей версии KinoTime,
включая тестовую команду `/zona`, отдельный запускатель и Dockerfile для Bothost.
Токены, api_hash, реальные администраторы, базы, сессии и файлы фильмов не включены.
Файл `data/config.py` в этом архиве читает BOT_TOKEN и ADMIN_IDS из окружения.
Локальный файл конфигурации на компьютере разработчика не изменён.

Проверены программные сценарии сохранения базы, ожидания API, однократного logOut,
контроля процессов и очереди Zona. Сборка C++-образа, ресурсы тарифа Bothost и реальная
отправка через этот контейнер пока не проверены: Docker Engine в среде разработки не запущен.
Возможность собственного Dockerfile описана хостингом, но успешное развёртывание
конкретного образа необходимо подтвердить по логам Bothost.

## 1. Подготовить данные

1. В панели Bothost откройте действующего бота.
2. Запишите текущие переменные окружения и путь рабочей SQLite-базы (`DATABASE_PATH`).
   Не публикуйте токены, ключи и полный список окружения в чатах.
3. Остановите бота кнопкой панели и скачайте резервную копию данных через файловый менеджер.
   Сохраните папку `/app/data`, а также базу вне этой папки, если она там находится.
   При наличии файлов `-wal`/`-shm` сохраняйте их вместе с SQLite-базой.
4. Рабочая база должна находиться в сохраняемой папке, например `/app/data/bot.sqlite`.
   Если имя другое, сохраните его и укажите фактический путь в DATABASE_PATH.
5. Если база пока в корне `/app`, перенесите её в `/app/data` при остановленном боте
   через файловый менеджер, затем задайте DATABASE_PATH.
   После резервирования исходную копию можно оставить; не заменяйте рабочую базу файлом из архива.

Не создавайте второго одновременно работающего бота с тем же токеном.
При смене сервера с уже существующим локальным Bot API нужен отдельный перенос его данных;
описанный ниже первый переход рассчитан на бота, который сейчас использует облачный API Telegram.

## 2. Установить исходники без переключения API

1. Загрузите полный архив в обновление исходников существующего бота Bothost
   либо замените серверные исходники в подключённом репозитории.
   Не загружайте архив как файл внутрь `/app/data` — это не установка исходников.
2. В «Дополнительных настройках» включите «Использовать собственный Dockerfile».
   В корне архива уже лежит нужный `Dockerfile`.
3. Сохраняйте Docker ENTRYPOINT/CMD из образа. Главный файл приложения — `app.py`;
   не указывайте `setup.sh` или скрипт Docker Compose.
4. Задайте переменные:

| Переменная | Значение |
|---|---|
| `BOT_TOKEN` | Текущий токен бота. Bothost может уже передавать его автоматически |
| `ADMIN_IDS` | Числовой Telegram ID вашего аккаунта; несколько — через запятую |
| `DATA_DIR` | `/app/data` |
| `DATABASE_PATH` | Реальный путь рабочей базы, например `/app/data/bot.sqlite` |
| `BOTHOST_LOCAL_API` | `0` на этапе проверки новой сборки |

`BOT_API_BASE` на этом этапе должен быть прежним облачным адресом `https://api.telegram.org`
или отсутствовать. Остальные рабочие переменные — TMDB, веб-панель и т.д. — сохраните.
Значения секретов вводятся только в настройках Bothost, не в исходниках и не в терминале.

5. Выполните пересборку/деплой через панель хостинга.
   Первый раз компилируется официальный Bot API из закреплённого коммита;
   сборка может занять долгое время и потребовать больше памяти, чем обычный Python-бот.
   Компиляция ограничена одним параллельным заданием. Если хостинг прерывает сборку
   по памяти или времени, сохраните текст ошибки без секретов; это ещё не переключает Telegram.
6. В логах ожидается `Встроенный Bot API выключен: BOTHOST_LOCAL_API=0.`
7. Проверьте `/start`, свой каталог и `/admin`. Убедитесь, что произведения и пользователи сохранены.

Если база по DATABASE_PATH отсутствует, запуск останавливается вместо создания пустого каталога.
`BOTHOST_ALLOW_EMPTY_DB=1` предназначен только для действительно нового бота без существующей базы.

## 3. Включить большой Bot API

Только после успешного этапа 2:

1. Получите реквизиты приложения Telegram на `https://my.telegram.org/apps`,
   если ещё не получали их. Это отдельные значения от токена BotFather.
2. Остановите текущий контейнер бота кнопкой панели.
3. Добавьте или измените переменные:

| Переменная | Значение |
|---|---|
| `TELEGRAM_API_ID` | Числовой api_id |
| `TELEGRAM_API_HASH` | api_hash, 32 шестнадцатеричных символа |
| `BOTHOST_LOCAL_API` | `1` |
| `BOTHOST_MIGRATE_CLOUD` | `1` — явное разрешение однократного выхода из облачного API |

4. Примените переменные с пересозданием контейнера через панель Bothost.
   Кнопка простого перезапуска не всегда обновляет окружение; используйте действие применения настроек/деплоя.
5. Запускатель сначала проверит локальный API, затем выполнит облачный `logOut`,
   сохранит отметку и проверит локальный `getMe`. Только после этого стартует KinoTime.

Ожидаемые строки:

```text
Встроенный Bot API отвечает на 127.0.0.1:8081.
Первый переход с облачного API выполнен и сохранён.
Локальный getMe подтверждён. Запускаю KinoTime.
```

6. После успешного запуска удалите `BOTHOST_MIGRATE_CLOUD` из переменных или задайте `0`.
   `BOTHOST_LOCAL_API=1` оставьте. Отметка хранится в той же постоянной папке, что и данные API;
   повторный запуск не выполняет logOut даже при случайно оставленном флаге `1`.

После облачного logOut Telegram ограничивает возврат в облачный API на 10 минут.
Не выполняйте его вручную дополнительно и не включайте параллельный экземпляр бота.

## 4. Проверить Zona

Из личного аккаунта администратора отправьте боту:

```text
/zona https://w1.zona.im/tvseries/dzhek-richer-2022
```

Выберите LostFilm / 480p, затем отслеживайте `/zona_status`.
Результат проверки — полная серия пришла в Telegram, открывается и воспроизводится со звуком.
Для уже отправленного файла повторная выдача не требует скачивания.

## Данные, порты и обновления

- Исходники образа лежат в `/opt/kinotime`, служебный запускатель — в `/usr/local/bin`.
  Поэтому подмена `/app` исходниками Bothost не скрывает исполняемые файлы.
- База — по DATABASE_PATH, резервные копии — по BACKUP_DIR (обычно `/app/data/backups`).
- Данные и отметка Bot API — `/app/data/telegram-bot-api`.
- Временные и готовые загрузки Zona — `/app/data/zona`.
- Порт 8081 слушает только внутри контейнера и не должен получать внешний домен.
- Для веб-панели сохраните WEB_ENABLED=1 и WEB_PUBLIC_URL с вашим доменом.
  Если WEB_HOST/WEB_PORT не заданы, запускатель использует `0.0.0.0` и PORT платформы
  (либо 8088). Внешний порт панели нельзя назначать 8081.
- Обновления выполняются пересборкой через панель Bothost. Веб-терминал Docker не управляет.
- Если падает один из двух процессов, запускатель останавливает второй и завершает контейнер.
  Дальнейший перезапуск зависит от политики хостинга.
- При штатной остановке сначала завершается бот, затем API. При жёстком отключении
  очередь восстанавливает загрузки; неоднозначная отправка требует проверки чата перед повтором.

## Если не запустилось

| Сообщение | Действие |
|---|---|
| Не найден DATABASE_PATH | Проверить файл через менеджер; не разрешать пустую базу для действующего бота |
| Нет BOT_TOKEN / ADMIN_IDS | Добавить значения в настройки окружения |
| Нет TELEGRAM_API_ID / HASH | Заполнить реквизиты приложения Telegram |
| Первый переход не подтверждён | Остановить старого бота; задать BOTHOST_MIGRATE_CLOUD=1 |
| Отметка переноса не соответствует данным | Не удалять её автоматически; проверить токен и восстановление всей папки API |
| Bot API завершился при запуске | Проверить логи, память, свободный диск, сборку и реквизиты |
| Ошибка logOut | Бот ещё не запущен; проверить соединение и токен, затем повторить |
| Ошибка getMe после logOut | Отметка уже сохранена; исправить сеть/API и перезапустить без нового logOut |
| Сборка прервана / Killed | Проверить ограничения сборки и ресурсы тарифа; перенос Telegram ещё не выполнен |
| Видео не пришло | Посмотреть `/zona_status` и логи; сохранить ошибку без токенов |
