# Запуск веб-панели KinoTime

**Для установки на Linux или Windows используйте [Docker-установщик](DOCKER_SETUP.md):**
`bash setup.sh` или `.\setup.ps1`. Он сохраняет настройки и запускает сервисы
в фоне. Ниже оставлена ручная настройка без установщика.

Веб-панель запускается внутри `app.py`. Отдельный веб-процесс и сборка JavaScript
не нужны. По умолчанию панель выключена: для включения задайте `WEB_ENABLED=1`
**перед запуском бота**. После изменения настроек перезапустите бот.

Это инструкция для существующей реализации. Проверка реальной передачи файлов
размером 2 и 4 ГБ на рабочем сервере ещё требуется.

## 1. Быстрый запуск на Windows

Откройте PowerShell в корне проекта. Если бот уже работает, сначала остановите
его через Ctrl+C в его терминале: одновременно должен работать один экземпляр.
Токен `BOT_TOKEN` и Telegram ID администраторов `ADMIN` остаются в `data/config.py`.

```powershell
uv sync --frozen
uv run --frozen python tools/backup_database.py bot.sqlite
$env:WEB_ENABLED = "1"
$env:WEB_HOST = "127.0.0.1"
$env:WEB_PORT = "8088"
$env:WEB_PUBLIC_URL = "http://127.0.0.1:8088"
$env:BOT_API_BASE = "https://api.telegram.org"
uv run --frozen python app.py
```

Команда резервирования рассчитана на существующую `bot.sqlite` в корне проекта.
Если задан `DATABASE_PATH`, используйте соответствующий путь; при первом запуске
без базы пропустите резервирование. Миграции выполняются автоматически.

Отправьте боту `/web` **в личном чате с аккаунта администратора** и откройте
полученную ссылку на этом же компьютере. Ссылка одноразовая, действует 10 минут;
вход сохраняется на 12 часов. Если ссылка истекла, запросите новую через `/web`.
Обычное открытие адреса без входа покажет только экран авторизации.

В этом режиме код ограничивает новую веб-загрузку **50 000 000 байт (50 МБ)**.
Чтобы загружать серии до **2 000 000 000 байт (2000 МБ)**, выполните раздел 2.
Наличие Premium у администратора само по себе не повышает лимит веб-загрузки.

Переменные `$env:…` действуют в текущем PowerShell и запущенных из него процессах.
При новом запуске задавайте их снова либо настройте окружение службы.
**Файл `.env` приложение автоматически не читает.** Копирования `.env.example`
в `.env` недостаточно для включения панели.

## 2. Загрузка до 2000 МБ: локальный Telegram Bot API

Нужен отдельный процесс официального `telegram-bot-api` с флагом `--local`.
Локальный здесь означает собственный API-сервер: он может работать на VPS рядом
с ботом. [Telegram документирует лимит 2000 МБ для этого режима](https://core.telegram.org/bots/api#using-a-local-bot-api-server).

### Подготовка API-сервера

1. Получите собственные `api_id` и `api_hash` по
   [инструкции Telegram](https://core.telegram.org/api/obtaining_api_id).
   Это реквизиты приложения Telegram, отдельные от токена бота.
2. Соберите и установите официальный сервер по
   [генератору инструкций для вашей ОС](https://tdlib.github.io/telegram-bot-api/build.html).
   Выберите Windows или ОС вашего VPS. Установка Python-зависимостей проекта
   этот исполняемый файл не устанавливает.
3. Запустите сервер в отдельном терминале. Пример PowerShell, если исполняемый
   файл уже добавлен в PATH:

```powershell
$env:TELEGRAM_API_ID = "ВАШ_API_ID"
$env:TELEGRAM_API_HASH = "ВАШ_API_HASH"
New-Item -ItemType Directory -Force runtime/telegram-bot-api | Out-Null
Set-Location runtime/telegram-bot-api
telegram-bot-api --local --http-port=8081
```

Если бинарный файл не в PATH, вместо `telegram-bot-api` укажите его полный путь,
например `& "C:\telegram-bot-api\bin\telegram-bot-api.exe" --local --http-port=8081`.
Сохраните рабочую папку API-сервера между перезапусками. Терминал должен оставаться
открытым; для постоянной работы настройте запуск как службу средствами вашей ОС.

Для Linux задайте те же реквизиты через `export TELEGRAM_API_ID='…'` и
`export TELEGRAM_API_HASH='…'`, затем выполните
`telegram-bot-api --local --http-port=8081` в постоянной рабочей папке сервиса.

Порт 8081 должен быть доступен боту, но закрыт от публичного интернета
межсетевым экраном. Если бот и API находятся в разных контейнерах, используйте
внутреннюю сеть контейнеров: `127.0.0.1` внутри контейнера указывает на него самого.
Реквизиты, флаги и порядок установки описаны также в
[README официального сервера](https://github.com/tdlib/telegram-bot-api#usage).

### Однократный переход с облачного API

Сначала остановите работающий polling-бот. Затем вызовите `logOut` на облачном
API. **Следующая команда действительно отключает бота от облачного API**;
выполняйте её только при готовом локальном сервере, при переходе, а не при каждом
перезапуске. После успешного `logOut` локальный сервер доступен сразу, а возврат
к облачному API запрещён Telegram на 10 минут.
[Правило перехода в документации Telegram](https://core.telegram.org/bots/api#logout).

В PowerShell из корня проекта выполните:

```powershell
@'
import asyncio
from aiogram import Bot
from data.config import BOT_TOKEN

async def main():
    bot = Bot(token=BOT_TOKEN)  # По умолчанию именно облачный API.
    try:
        result = await bot.log_out()
        print("logOut:", result)
    except Exception as error:
        print("logOut failed:", type(error).__name__)
        raise SystemExit(1)
    finally:
        await bot.session.close()

asyncio.run(main())
'@ | uv run --frozen python -
```

В Linux этот же Python-код можно выполнить через `uv run --frozen python -`
с heredoc (`<<'PY'`, затем код, затем отдельная строка `PY`). Продолжайте после
`logOut: True`; при ошибке сначала устраните причину перехода.

Теперь в терминале бота, из корня проекта:

```powershell
$env:WEB_ENABLED = "1"
$env:WEB_HOST = "127.0.0.1"
$env:WEB_PORT = "8088"
$env:WEB_PUBLIC_URL = "http://127.0.0.1:8088"
$env:BOT_API_BASE = "http://127.0.0.1:8081"
uv run --frozen python app.py
```

Должны работать оба процесса: `telegram-bot-api` и `app.py`. Откройте новую
ссылку `/web`: панель должна показывать лимит **2000 МБ**. Само изменение
`BOT_API_BASE` не устанавливает сервер и не включает у него режим `--local`.

## 3. Доступ к панели на VPS

### Через SSH-туннель, без домена

На VPS задайте боту `WEB_ENABLED=1`, `WEB_HOST=127.0.0.1`, `WEB_PORT=8088`,
`WEB_PUBLIC_URL=http://127.0.0.1:8088` и адрес своего API в `BOT_API_BASE`.
В Linux переменные задаются перед запуском, например:

```bash
export WEB_ENABLED=1
export WEB_HOST=127.0.0.1
export WEB_PORT=8088
export WEB_PUBLIC_URL=http://127.0.0.1:8088
export BOT_API_BASE=http://127.0.0.1:8081
uv run --frozen python app.py
```

На компьютере администратора откройте отдельный терминал:

```powershell
ssh -N -L 8088:127.0.0.1:8088 USER@SERVER
```

Замените `USER@SERVER` на пользователя и адрес VPS. Оставьте SSH-соединение
открытым, запросите `/web` и откройте ссылку на этом компьютере. Локальный порт
8088 должен быть свободен. Без туннеля адрес `127.0.0.1` не ведёт на VPS.

### Через домен и HTTPS

Направьте DNS своего домена на VPS и настройте HTTPS reverse proxy.
Приложение отклоняет удалённый `WEB_PUBLIC_URL` без HTTPS.
Пример для установленного Caddy, работающего на том же хосте, что и бот:

```caddyfile
kino.example.com {
    reverse_proxy 127.0.0.1:8088
}
```

Замените домен на свой, обеспечьте доступ к портам 80/443 для Caddy и получение
сертификата. У бота задайте `WEB_PUBLIC_URL=https://kino.example.com`, оставьте
`WEB_HOST=127.0.0.1`, затем перезапустите его. Настройка домена и прокси выполняется
отдельно; проект их автоматически не создаёт.

При использовании Nginx в уже настроенном HTTPS `server`:

```nginx
location / {
    client_max_body_size 9m;
    proxy_request_buffering off;
    proxy_read_timeout 120s;
    proxy_pass http://127.0.0.1:8088;
    proxy_set_header Host $host;
}
```

Браузер передаёт файл частями по 8 МиБ, поэтому прокси должен пропускать запросы
такого размера. Для контейнерного запуска бота задайте `WEB_HOST=0.0.0.0` внутри
контейнера и публикуйте порт только на loopback хоста (`127.0.0.1:8088:8088`),
если прокси работает на хосте. Сохраняйте `/app/runtime` на постоянном томе,
как описано в основном README; там находятся база и временные загрузки.

## 4. Настройки хранения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WEB_ENABLED` | `0` | `1` включает веб-сервер |
| `WEB_HOST` | `127.0.0.1` | Адрес прослушивания |
| `WEB_PORT` | `8088` | Порт веб-панели |
| `WEB_PUBLIC_URL` | `http://127.0.0.1:8088` | Адрес для ссылки входа, без пути и параметров |
| `BOT_API_BASE` | `https://api.telegram.org` | Адрес API, без `/bot<TOKEN>` |
| `UPLOAD_DIR` | `<DATA_DIR>/uploads` | Временные файлы веб-загрузки |
| `UPLOAD_QUOTA_BYTES` | `20000000000` | Общая квота активных веб-загрузок, 20 ГБ |

Без явно заданного `DATA_DIR` служебная папка — `runtime`, а рабочая база —
`bot.sqlite` в корне. Если задать `DATA_DIR`, путь базы по умолчанию изменится
на `<DATA_DIR>/bot.sqlite`. Чтобы сохранить выбранную базу при смене папок,
задайте `DATABASE_PATH` явно. Не переключайтесь случайно на пустую базу.

У процесса бота должны быть права записи в папки базы, резервных копий и загрузок.
Квота относится к веб-загрузкам; хранилище локального Bot API использует место
отдельно. После успешной передачи в Telegram временный файл панели удаляется,
в базе остаётся `file_id`. Черновики и привязки файлов сохраняются в SQLite.

## 5. Проверка и частые ошибки

1. Убедитесь, что бот отвечает на `/start` и `/web`.
2. Откройте ссылку, создайте черновик и загрузите небольшой тестовый файл.
3. Дождитесь статуса «Готов», опубликуйте и проверьте выдачу по коду в боте.
4. Затем проверьте крупный файл через веб и отдельно ручной сценарий до 4 ГБ.
   Публикация добавляет контент в настоящий каталог: используйте подходящую
   тестовую карточку и после проверки удалите её через админку.

| Проблема | Что проверить |
|---|---|
| «Веб-панель пока не включена» | `WEB_ENABLED=1` задан именно процессу бота, бот перезапущен |
| Страница не открывается | Работает `app.py`, свободен порт 8088, открыт SSH-туннель или настроен HTTPS-прокси |
| В панели лимит 50 МБ | `BOT_API_BASE` всё ещё указывает на облачный API |
| Показано 2000 МБ, но отправка не работает | Локальный API работает с `--local`, выполнен переход `logOut`, адрес доступен из процесса бота |
| «Откройте панель по её основному адресу» | Адрес браузера в точности совпадает с `WEB_PUBLIC_URL`, включая протокол, имя хоста и порт |
| Ссылка входа не работает | Получите новую через `/web`, проверьте свой ID в `ADMIN` |
| HTTP 413 при загрузке | Увеличьте лимит размера запроса прокси хотя бы до 9 МиБ |
| Не хватает места | Проверьте диск и квоту; удалите ненужные незавершённые загрузки через панель |
| Обрыв передачи с компьютера | Откройте сохранённый черновик и выберите тот же исходный файл для продолжения |

Для выключения панели остановите бот, задайте `WEB_ENABLED=0` и запустите снова.
Это не меняет `BOT_API_BASE` и не удаляет черновики.

Инструкция повседневной работы: [WEB_ADMIN.md](WEB_ADMIN.md).
