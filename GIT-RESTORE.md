# KinoTime — Git checkpoint, 28 октября 2026

Полный комплект исходников для сохранения в Git и развёртывания на Bothost.
Содержимое архива помещается в КОРЕНЬ существующего репозитория, без дополнительной папки.
Токенов, личных конфигураций, баз, сессий и видео здесь нет.
База и исходные настройки сохранены в отдельном личном архиве отката от 28 октября.

## Что подготовлено
- Корневой Dockerfile предназначен для Bothost; исходный VPS-вариант сохранён
  в deploy/Dockerfile.vps. Текущие исходники включают прототип Zona.
- data/config.py читает BOT_TOKEN (или TELEGRAM_BOT_TOKEN) и ADMIN_IDS из окружения.
- .gitignore исключает базы, секретные env-файлы, личные архивы и выходные каталоги.
- Переменные задаются в панели хостинга. .env.example — только образец,
  приложение не читает .env автоматически.
- Основная база для восстановления: отдельная проверенная копия с 21 карточкой
  и 2052 записями TelegramStorageFiles. Её нельзя помещать в репозиторий.

## Сохранить точку отката в Git
1. Сохраните текущие переменные Bothost и резервную копию /app/data.
   Если Git обновляет бота автоматически, сначала отключите автоматическое развёртывание.
2. В своей копии Git-репозитория проверьте git status и сохраните незавершённую работу.
   До замены файлов сохраните нынешнее состояние отдельным коммитом/тегом.
3. Распакуйте содержимое этого архива в корень репозитория. Не добавляйте личный архив.
4. Проверьте изменения и список отслеживаемых секретов:

   git status --short
   git ls-files "*.sqlite*" "*.session*" ".env" ".deploy.env" "*.zip"

   Если вывод второй команды не пустой, исключите эти файлы из индекса через
   git rm --cached -- <точный путь>. Это сохраняет локальную копию.
   .gitignore не удаляет файлы, которые уже отслеживаются Git.
   data/config.py должен содержать только чтение окружения, без настоящего токена.
5. Создайте коммит с подготовленными исходниками. Включайте только проверенные изменения.
   Пример команды после проверки:

   git add .
   git commit -m "Save KinoTime checkpoint 2026-10-28"
   git tag -a kinotime-checkpoint-2026-10-28 -m "KinoTime source checkpoint"

   Если тег уже существует, выберите новый; не перезаписывайте существующий тег.
6. Отправьте свою рабочую ветку и тег обычным git push, затем
   git push origin kinotime-checkpoint-2026-10-28.
   Архив сам не создаёт коммит и ничего в удалённый Git не отправляет.

## Развёртывание на Bothost
Следуйте docs/BOTHOST_ZONA_SETUP.md. Нужны BOT_TOKEN, ADMIN_IDS, DATA_DIR=/app/data,
DATABASE_PATH с фактическим путём базы и включённый собственный Dockerfile.
Не меняйте действующий BOT_API_BASE и режим API без отдельной проверки его состояния.
Если бот сейчас на облачном API, первоначальная проверка проходит с BOTHOST_LOCAL_API=0.
Если уже используется локальный API, сначала определите, где его данные и как он запущен:
данные API не хранятся в Git, повторный автоматический logOut делать нельзя.
Обновление исходников не восстанавливает базу: существующая база остаётся в /app/data.

## Вернуть код этой точки отката
Работайте в чистой копии репозитория, без несохранённых изменений.
Создайте отдельную ветку из тега, например:

   git switch -c restore-2026-10-28 kinotime-checkpoint-2026-10-28

После проверки выберите эту ветку для развёртывания либо перенесите восстановление
обычным коммитом в ветку, которую отслеживает Bothost. Force push не нужен.
При откате на более старый код проверяйте совместимость схемы базы.
Текущая версия ожидает схему 24; нельзя без проверки заменять новую базу старой.
